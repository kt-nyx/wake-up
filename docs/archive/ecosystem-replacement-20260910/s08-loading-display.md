## Behavior and activation

The ordinary **Show Wake-Up loading display** setting persists as `loadingDisplay=false`; **Record loading display diagnostics** persists as `loadingDisplayDiagnostics=false`. Missing keys retain those defaults. Changing either setting does not alter the current launch. The master switch still disables selection, and explicit development controls still take precedence over settings. The selectors are `--wake-up-loading-display=on` and, only with the display selected, `--wake-up-loading-display-diagnostics=on`, under the existing candidate-mode contract. Duplicate or invalid display selectors do not activate it. Existing fixture presets/selectors were not changed.

[LoadingDisplayRuntime](../../../src/WakeUp/Startup/LoadingDisplayRuntime.cs) observes the game's own stage text and adds a compact upper-left panel during native loading repaints. Native stage text remains translated by the game. The panel shows a count of loaded mods, with names hidden; it does not enumerate or draw a list every frame or request icons/previews. Native background, tips and drawing remain intact. This is an added information panel, not a replacement for the loading closure.

The timer explicitly starts when Wake-Up begins observing after its initialization; it excludes earlier process/bootstrap work. There is no percentage or estimated finish time. Stages remain as coarse as the game's messages, such as loading definitions and initializing the interface. Main-thread loading work cannot display a new frame until it returns to the game loop. Some stages may therefore be recorded but never visibly drawn. No waits or extra frames were added to expose them.

[LoadingDisplayState](../../../src/WakeUp/Startup/LoadingDisplayState.cs) keeps logical stage updates in memory. Cache sampling, text formatting and text-size calculation run at most once per 250 ms, apart from recalculating size when screen width changes. Ordinary native repaint events redraw cached content to keep it visible in Unity's immediate-mode GUI; suppressing those redraws between intervals would make it flicker. No per-item repaint requests, yielding, full-list rendering or extra graphics resources are introduced. These source bounds are not a measured overhead result.

The cache panel samples the S01/S07 consumer's existing counters through `PngRuntime.DisplaySnapshot()`. It distinguishes off, setup refusal, bypass, clear request, forced rebuild, reused entries, completed writes, misses, errors and storage-limit fallback. “Rebuilt” counts completed writes, including first builds, not every miss. A miss can remain uncached because an entry is ineligible or storage is full. Clear is reported as requested, with the maintenance receipt authoritative for its outcome. Disabled caching remains disabled. These totals refer only to Wake-Up's PNG/JPEG cache; no independent XML/language cache or supplier cache result is invented. No texture routing, supplier hook, cache format, quota or default changed.

The deeper option adds stage-change count, stored size and the latest storage reason to the panel, and records at most 64 stage transitions with observation-relative timestamps in `WakeUp/loading-display.jsonl`. The ordinary path records only installation/end/refusal and stage-change count. There is no per-mod attribution, callback timer or general profiler, and no summing of overlapping durations.

## Native integration and cleanup

Existing read-only ILSpy inspected the frozen game assembly. [Native research](../../../artifacts/s08/research/native-ui-notes.md) and eight decompiled types remain ignored under `artifacts/s08/research/`. Five method-body contracts guard the observed drawing/text/update/play-load functions; the source records their exact semantic fingerprints. Changed required native bodies refuse only this feature. This does not reintroduce a whole-game version gate.

The adapter installs an after-call observer (Harmony postfix) on `LongEventsOnGUI` and `SetCurrentEventText`. An exception-preserving observer (void finalizer) on `LongEventsUpdate` also captures newly dequeued events, whose text is assigned directly without the setter. The `DoPlayLoad` finalizer stops observation on escaping content-load errors; a `Root_Entry.Update` observer supplies menu cleanup. No method body, callback, constructor or original argument/result is replaced by these hooks.

Native `DrawLongEventWindowContents` remains unpatched. In particular, its repaint acknowledgment (`alreadyDisplayed`) still releases synchronous events that wait to be shown. The panel respects `forceHideUI` and a missing current event. The original deferred-callback list, action/callback order, native static-constructor calls and native cleanup remain unchanged. Asynchronous completion runs callbacks before clearing the current event; synchronous completion clears it first. Both remain native.

When the native queue ends, observed references and cached GUI content are released. This is an “ended” receipt, not proof that loading succeeded: native code catches some callback/constructor failures internally. Such swallowed failures are not individually observed by this display. Native logging/recovery and the independent menu observer remain authoritative. Escaping errors keep their original exception object and propagation behavior.

Loading Progress's active package declines display ownership before installation. Foreign patches on either native drawing method also refuse ownership, including patches installed later during mod construction; the published-patch guards are checked when drawing. The reason is retained in Wake-Up settings and its log. This does not disable or alter existing Loading Progress repaint coalescing or PNG/JPEG supplier integration. S14 still owns final verified conflict warnings; there is no new compatibility framework.
