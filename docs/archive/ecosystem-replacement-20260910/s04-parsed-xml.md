## What was measured and why this differs from the old catalog

The [old metadata catalog](../initial-loading-investigation.md) added validation and publication while still parsing source XML on warm hits: 6.276/6.146 seconds cold/warm all-mod loading versus 1.948 seconds original. That route remains closed under its tested premise. This probe actually replaces parsing with binary records describing XML nodes, a table of repeated names, node kinds, values, attribute/child counts and empty-element state. Reading records calls XML node constructors; it never calls `LoadXml` or reparses stored XML text. No competitor implementation was copied.

The independent [probe](../../../artifacts/s04-parsed-xml/Program.cs) links the unchanged S01 `OwnedCacheStore`, `CacheDigest` and `CacheLaunchPolicy`. A separate `XmlCache/v1` category exists only inside its ignored output directory. Warm work includes reading each current source, hashing its actual bytes, deriving a path/content/parser key, reading and integrity-validating the stored payload, then reconstructing a new document. The miss path hashes and parses the **same byte array**, so a later file change cannot separate the checked input from the parsed input. Its parser reproduces native UTF-8/BOM handling and reader settings. The key binds the probe format/settings and offline XML-library assembly identity; this is not a production effective-method/hook admission implementation.

The probe uses 8 MiB payload and 512 MiB store bounds, a 200,000-node/128-depth limit and source samples no larger than 2 MiB. Before binary capture it calls `CanPublish` with the full 8 MiB upper bound, then publication rechecks actual size. Each warm trial includes category initialization, reads, `Complete` and disposal. No application data or native loader is redirected to this category. No reusable in-memory trees are shared. These are probe bounds, not new product defaults.

The [sample receipt](../../../artifacts/s04-parsed-xml/sample.json) identifies **64 XML files / 708,912 source bytes**: eight size quantiles from Core and each of the first seven frozen manifest packages with at least eight definition files. Binary payloads total **886,577 bytes**, excluding store envelopes and usage data. Selection is a small varied cost sample, not actual active-folder discovery, a mod allowlist, or a representative coverage percentage. Duplicate versions in a package may be sampled; that cannot establish effective load order.

SDK 10.0.401 compiled the probe with the existing approved reference verifier. It executed actual native `LoadableXmlAsset(FileInfo, ModContentPack)` calls on **.NET 8.0.31**, without a game launch. Candidate parsing/reconstruction uses that same host's XML library. This is not RimWorld's Mono/Unity performance or compatibility evidence. ## Native flow, ownership and fallback findings

The game first chooses actual files, then creates real source assets, then imports their nodes into the combined document. Keeping those stages intact preserves which mod/file owns a definition and which override wins.

1. [DirectXmlLoader.XmlAssetsInModFolder](../../../artifacts/s04-parsed-xml/DirectXmlLoader.cs) visits effective folders in their supplied descending order. It recursively enumerates each folder without adding a sort, rejects dot-prefixed filenames and uses relative-path `TryAdd` so the first folder wins. It assigns result indexes before two worker threads plus the calling thread load files. Do not replace this with alphabetical discovery or key assets by basename.
2. [LoadableXmlAsset's file constructor](../../../artifacts/s04-parsed-xml/LoadableXmlAsset.cs) assigns the original `mod`, `name` and `fullFolderPath`, maps the selected file, strips an initial UTF-8 BOM, decodes UTF-8 and loads a fresh `XmlDocument`. Native settings ignore comments/whitespace, disable character checks and async reading; remaining reader defaults also matter. `FullFilePath` derives from the real fields. The string constructor, resources and virtual-directory loaders are separate paths.
3. A prospective integration would keep that constructor and its exception boundary, capture/hash an immutable snapshot at the actual byte-decoding boundary, and replace only its parse. Hashing the file in an earlier prefix and letting native code read it again is insufficient. Capturing only decoded characters is also not a claim to hash exact original bytes. A hit must stage a complete fresh document before replacing the constructor's local document; a failed decode must leave the ordinary reader available and native destination untouched. Constructor/parser method behavior and effective hooks must qualify at use, including after Prepatcher changes. No such interception was installed by this checkpoint.
4. [LoadModXML and CombineIntoUnifiedXML](../../../artifacts/s04-parsed-xml/LoadedModManager.cs) retain actual mod/input order. Combination imports each top-level node into a fresh destination and maps that new node to its original real asset. Preserve the exact importer and map. `ModContentPack.LoadDefs` is an iterator: hooks on its factory are not a scope around its eventual execution. [LoadPatches](../../../artifacts/s05-feasibility/ModContentPack.cs) independently uses the same file loader and sets operation `sourceFile` from the actual asset path.
5. A malformed/missing input follows the constructor's warning and null-document behavior, then native downstream diagnostics. Never cache failed parses or replace null with empty success. Native ignores source comments, but declarations, processing instructions, CDATA, significant whitespace, namespaces, attribute order and explicit empty-element state can remain observable. Keep patch operations, dependency filtering and inheritance entirely ordinary.

The [existing Wake-Up Gagarin integration](../../../src/WakeUp/Gagarin/GagarinCacheRuntime.cs) preserves real asset constructors and ordered imports when avoiding a redundant supplier parse. The pinned [supplier constructor postfix](../../../artifacts/ecosystem-review-20260909/sources/missilegirl/Source/Gagarin/Core/Patches/LoadableXmlAsset_Patch.cs) hashes `xmlDoc.OuterXml`; its `LoadDefs` postfix also reads patch XML for validation. Independent S04 should conservatively refuse competing/unknown constructor hooks, including this supplier ownership, rather than intercept the same parse twice. Unknown virtual/archive sources and unsupported transformations remain ordinary. Loading Progress changes surrounding flow and is not automatically an allowed hook. Disk assembly identity alone does not establish effective loading behavior.

## Focused evidence and limits

All 64 native parses matched the probe's same-settings parse and reconstructed structure, with **162,671 individual structural assertions**, not that many independent tests. A synthetic case also checks duplicate names, attribute-versus-element keys, namespaces, declaration/processing instruction, native comment suppression, CDATA, significant whitespace, explicit empty elements and independent copies after mutation.

The [34-assertion focused check](../../../artifacts/s04-parsed-xml/focused.json) additionally executes native folder discovery and combination on temporary files: override winners, identical basenames in distinct directories, hidden-file exclusion, changed folder order, indexed source maps and mod-reference identity. It verifies a same-size edit with restored timestamp changes the content key, the previously captured snapshot still parses its original content, corrupt entries miss and fall back to ordinary parsing, malformed XML throws, missing files throw and truncated payloads refuse. The mod is an uninitialized test identity used only for reference attribution; no colony or initialized mod state is exercised. Malformed/missing checks validate the probe's fallback inputs, not native Unity logging callbacks. Native error behavior above is a source finding.

Reproduce locally with `python artifacts/s04-parsed-xml/sample.py`, then `pwsh -NoProfile -File artifacts/s04-parsed-xml/run.ps1` and the same script with `focused`. The script checks the frozen manifest and uses approved GOG/Harmony references. Raw output is ignored. Product source, tests and build inputs are unchanged, so existing full regression results were trusted rather than rerun. No fixture guard was changed or bypassed for a fixture operation.
