## What the native method actually does

Read-only ILSpy inspection used the frozen GOG 1.6.4871 rev573 reference in fixture generation `20260904-182829-e058641c`. Its `Assembly-CSharp.dll` SHA-256 is `4a170804fbfefabdb620d8914e584e58f822a58c6e304dcb76a67003588dab28`, matching the inventory. The build's approved reference verifier separately checked the GOG/Harmony inputs. Decompiled research is ignored under [s02-research](../../../artifacts/ecosystem-review-20260909/s02-research).

`GenTypes.AllLeafSubclasses` immediately calls `AllSubclasses(baseType)` and captures that mutable list. It returns a LINQ `Where` iterator: filtering happens later, as callers enumerate it. Each predicate calls `AllSubclasses(child)` and tests the resulting list with `GenCollection.Any`. `AllSubclasses` returns an existing mutable cached list or constructs and caches the full descendant list using parallel LINQ (PLINQ). That parallel query does not promise a reconstruction order we can safely substitute.

Consequently, returning a cached set would change more than search cost. It could reorder or deduplicate results, hide later edits to child lists, and change exceptions when the outer list is edited during iteration. Reconstructing every child list would also risk changing later callers' observed ordering.

The native universe is `GenTypes.AllTypes`, built from the game's active assemblies. It differs from Harmony's assembly enumeration and has its own partial-load/error handling. Assembly loads alone do not refresh these native caches. `ClearCache`, replacement of the cached list, or direct list edits can change what later native searches see. Existing child lists remain authoritative until native code or a caller clears or changes them.

## Implementation and compatibility

[LeafSubclassRuntime](../../../src/WakeUp/TypeSearch/LeafSubclassRuntime.cs) substitutes only the leaf factory's `Where` call. The eager outer-list capture and original predicate remain. The returned iterator is still LINQ filtering the same list, including duplicates, abstract types, repeated enumeration and mutation exceptions.

For a child whose native descendant list is absent, [LeafSubclassIndex](../../../src/WakeUp/TypeSearch/LeafSubclassIndex.cs) walks the current types' complete inheritance chains and records every ancestor. A supported class absent from that set has no descendants. Only then does the adapter publish the empty mutable child list that native code would have produced, immediately before calling the original predicate. A nonleaf miss still runs native population. Existing child lists always win, including stale or caller-edited ones. This is a conservative adaptation of the proposed collect-descendants/eliminate-ancestors algorithm, not a replacement of all subclass queries.

The proof uses the full native type list rather than the possibly modified outer subclass list. It walks through missing intermediate ancestors and constructed generic bases without converting them to generic definitions. The latter matters because `IsSubclassOf` compares actual inherited types, not their generic definitions.

The reusable proof follows the native list's identity and modification version. A retained standard list enumerator detects even same-length element replacement through its normal `Reset` check; no private framework list field is used. The adapter reads already-published native cache fields and never initiates assembly enumeration. A missing type list, failed proof, custom `Type`, dynamic metadata, unsupported query type, excessive size, changed method or conflicting patch retains the original predicate. A partial native type list is used exactly as native searches would use it; S02 does not attempt to recover additional types or suppress enumeration failures.

Admission checks six original method bodies: the leaf factory and predicate, `AllSubclasses` and its predicate, the `AllTypes` getter, and the `AlertsReadout` constructor. The required native cache fields must have the expected static types. Published Harmony guards detect other mods' interception or rewriting of those methods, including later changes. The existing exact Harmony binary check remains upstream; no whole-game revision restriction was added. The original `GenCollection.Any` still runs, so S02 does not bypass that helper.

Only the existing code-search candidate selection activates S02, after the name-search component installs successfully. An S02 refusal leaves that component intact. There is no new setting, dependency or launch selector. Prepatcher remains required; on-demand loading remains optional and off by default. The corrected lifetime restricts work to the thread executing the guarded `AlertsReadout` constructor. A prefix acquires exclusive ownership of that scope; a finalizer closes it and clears the ancestor proof and thread ownership on return or exception. Nested constructors temporarily suspend reuse; concurrent constructors on other threads retain native searches. The owning constructor thread may differ from Wake-Up's installation thread. Outside the scope, filtering uses the original predicate directly. Native child caches remain native-owned. The name-search menu cutoff is unchanged; leaf admission uses the recorded candidate selection, not the completed name-search window.

The proof is bounded by the existing 250,000-type limit, at most 250,000 recorded ancestors and 2,000,000 ancestor steps. Its cost is one type-list traversal plus ancestry walking per observed list version. It avoids one native full-list search per proven terminal child cache miss. Branch misses still incur native searches, and warmed native child lists need no proof construction. S02 therefore does **not** claim that every hierarchy is processed in linear time or that its setup cost always pays off.
