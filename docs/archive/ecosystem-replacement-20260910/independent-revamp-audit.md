# Independent Wake-Up revamp audit

> Dated evidence: identities, results and pending steps below describe this report's original checkpoint. For the combined offline candidate and superseding decisions, see [current state](../../current-state.md), [current scope](retained-features.md) and [R5](r5-combined-offline-review.md). Historical live results do not qualify the new package.

Audit date: 10 September 2026. Dispatch: `wake-up-independent-audit-9fb2318`.

**Wake-Up remains a useful loading optimizer, but this revamp did not deliver full ecosystem replacement. Most of the measured speed advantage already existed in public 0.2.1. The additions improve translation application, cache maintenance, selected texture reuse, and some loading interactions; they leave the largest replacement gaps—independent XML caching, deferred assets, and broad texture preparation—open.**

On the tested French workload, the new default configuration was essentially level with the old release and slightly slower in the mean. Selecting translation/routing saved about 1.09 seconds with fresh application caches; selecting every retained option with populated caches saved about 2.54 seconds against old supported options. Those are useful but modest **bundle** results. They are not evidence that each new option helps, that English loads faster, or that users can remove the other optimizers still present in the comparisons.

The implementation generally makes careful, limited changes and preserves ordinary behavior when it cannot establish compatibility. This audit nevertheless identifies an incomplete routing compatibility guard, misleading activation/status wording, and practical preparation limits. These findings do not establish observed save corruption or explain the entire measured timing difference. Ordinary Windows colony entry has bounded evidence; the shared engine error and current Linux qualification remain unresolved.

## Every comparator and its useful loading capabilities

“Replacement” here means retaining a mod's useful loading behavior after removing it. Faster work **inside** an installed supplier is assistance, not independent replacement. A current repository head is not automatically the bytes of its latest Workshop or GitHub release. Source-unavailable entries retain documented capabilities and explicit uncertainty; absence of inspected code is not evidence of absent functionality.

In the tables, **native** means the game's original behavior. **XML** is the structured data defining game content; patches modify that data, and replay caches reuse a previous processed result. **Reflection** finds program types, fields and methods while the game runs. **DDS** stores textures in a form the graphics system can consume directly; **mip levels** are smaller image versions, and an **atlas** combines multiple textures for rendering. These are different loading stages, so improving one does not replace the others.

### Corrections and implementation lessons from independent research

**BetterLoading was under-described in the original research.** The historical fork's [`1StageReadXML.cs:41–73`](https://github.com/SlavRim/RimworldBetterLoading/blob/ed5a285322a2381084cfea81bf452ee9c7e75050/Stage/InitialLoad/1StageReadXML.cs#L41) actively replaces `LoadModXML` with parallel `LoadDefs`; [`5StageConstructDefs.cs:76–90`](https://github.com/SlavRim/RimworldBetterLoading/blob/ed5a285322a2381084cfea81bf452ee9c7e75050/Stage/InitialLoad/5StageConstructDefs.cs#L76) installs a type-name/namespace memo. The separate parallel definition-construction hook is commented out. The active XML query lacks `AsOrdered`, whereas the inspected native loader appends mods in order; potential ordering and third-party threading changes deserve scrutiny. This is a source concern, not a reproduced wrong-definition result. A slow XML-cache format does not disprove an ordered parallel-read technique; archived worker failures still need reconciliation before another trial.

**FGL original and Continued should not be treated as identical.** Continued adds concurrency/lifetime/ownership safeguards and avoids the original type patch's null-result caching. Its [persisted XML-miss shortcut](https://github.com/mushroomTW/FasterGameLoading---Continued/blob/0132c10a3185f578815fb1dba012b7b24f78d5e3/Source/XMLLoadingCache/XMLNode_SelectSingleNodes_Patch.cs#L167) still answers from a query string without receiving the current query document. Wake-Up's live, mutation-aware query scope avoids that assumption. The original seven XML comparisons remain narrow reproduced historical evidence for YaOpt/Hyperdrive/Wake-Up helper behavior, not current game failure rates; their [raw results](../../../artifacts/ecosystem-review-20260909/xml-check-results.json:1) show seven Wake-Up matches, three YaOpt mismatches and five Hyperdrive mismatches. No new game reproduction occurred here.

**YaOpt supplies real ideas and real tradeoffs.** Its [successful translation map](https://github.com/szszss/YetAnotherOptimizer/blob/ab60621f071fbee3e4f1a92bb163c2760b8605bf/Source/YaOpt/Helpers/DefInjectionHelper.cs#L14) is an actual useful algorithmic reference. Its [iterator `Current`](https://github.com/szszss/YetAnotherOptimizer/blob/ab60621f071fbee3e4f1a92bb163c2760b8605bf/Source/YaOpt/Helpers/XPathReducer.cs#L35) dequeues, explaining the separately preserved check where reading it twice advances the value. Its [pending-texture load](https://github.com/szszss/YetAnotherOptimizer/blob/ab60621f071fbee3e4f1a92bb163c2760b8605bf/Source/YaOpt/Helpers/ContentManager.cs#L478) removes pending state before success and its pre-render path drains the restoration queue. Wake-Up did not copy those mechanisms. Avoiding their defects is compatible with admitting that the useful deferred-loading capability remains missing.

**Independent caches need more than file existence and package IDs.** DefLoadCache's [early input bypass](https://github.com/FluxxField/rimworld-defload-cache/blob/f674263b5d17e5a2191828d2003cff61e2b5b1c0/src/Hook/CacheHook.cs#L177) can skip original loading before a later cache read succeeds; the same source clears the one-shot skip flag before later reuse checks. These are static fallback/control concerns, not newly observed runtime failures. FastLoader's [identity](https://github.com/solaris0115/FastLoader/blob/d95ae707661e46ff50a04b39d90173f6b90ed1e6/Project/Source/FastLoaderRuntime.cs#L960) binds format/game/ordered packages rather than all current content, and its author documents manual rebuilding after edits. Its [texture capture](https://github.com/solaris0115/FastLoader/blob/d95ae707661e46ff50a04b39d90173f6b90ed1e6/Project/Source/TextureRawCache.cs#L670) uses readback/recompression with one mip, rather than preserving the full native processed object. Wake-Up is stronger on automatic image validity/fidelity, but over a smaller feature set.

Gagarin checks actual XML-derived content, but Wake-Up's assistance preserves the supplier's cache policy rather than independently proving arbitrary custom patch effects replay-safe ([supplier input checks](https://github.com/ViralReaction/MissileGirl/blob/3170983d90e726f47f105dd2f426af8c3ce60e29/Source/Gagarin/Core/Patches/LoadableXmlAsset_Patch.cs#L42), [Wake-Up admission](../../../src/WakeUp/Gagarin/GagarinCacheRuntime.cs:74)). Treat this as a dependency boundary, not a newly proven stale-cache incident. Claims of safer Wake-Up-owned texture storage must not be generalized to all supplier-owned XML data.

Other reviewed defects/tradeoffs were not transplanted: historical Fish's [mip helper](https://github.com/bbradson/Performance-Fish/blob/a99972001e02d553a738611726cd9577ff41f86e/Source/PerformanceFish/Rendering/TextureLoadingPatches.cs#L127) replaces only its local parameter; Loading Progress's [constructor replacement](https://github.com/ilyvion/loading-progress/blob/bcd71bafd994b206ed644df0ae56583beb047646/Source/ilyvion.LoadingProgress/StaticConstructorOnStartupUtilityReplacement.cs#L31) changes surrounding hook timing while preserving a later hook notification; old RIMMSLoadUp changes patch completion timing. These are reasons to examine semantics, not to pronounce entire mods defective or faster/slower without execution evidence. Wake-Up's retained repaint assistance does not repair all supplier scheduling choices.

### What was already in public 0.2.1

Comparing public source directly with the current tree shows that definition/template searches, Harmony fallback type search, Gagarin parsed-XML assistance, Character Editor preset reuse, Loading Progress repaint coalescing, Giddy-Up center-column texture readback, and processed PNG caching all predate the revamp. Several supplier/search implementations are unchanged, while image caching and type-search wiring were extended. The principal additions are `Caching/`, `Translation/`, `Assets/`, leaf-subclass support, the display/background modules, preparation, and JPEG integration.

That distinction matters more than the total new source size. A large source addition can implement controls, refusal rules, recovery and UI without removing a large block of loading work. The old release already supplied the major absent-to-Wake-Up improvement in these captures. Historical individual-feature percentages use different workloads and must not be added or reassigned to this revamp. See [archived retained results](../results.md:20).

## Implementation quality and actionable findings

### What is sound in the retained design

**Translation application changes less than the supplier-inspired alternatives.** It narrows the native duplicate-search input; the game's assignment, normalization, list behavior and warnings still run. Scopes are per package/pass, index only successful assignments, invalidate on nested/concurrent use or changed dictionaries, and cap entries at 65,536. Unknown native bodies or foreign patches refuse the optimization. The native first-success/failed-retry distinctions are real correctness requirements, not gratuitous process. See [translation installation and scope](../../../src/WakeUp/Translation/TranslationRuntime.cs:66), [candidate selection](../../../src/WakeUp/Translation/TranslationRuntime.cs:179), and [successful-record/index handling](../../../src/WakeUp/Translation/TranslationRuntime.cs:200). Sampled live output and stage measurements support this narrow feature; they do not prove every custom translation consumer equivalent.

**Texture restoration retains actual processed output.** Capture preserves native conversion/compression and mip levels (smaller image versions used when rendering at distance), sampler settings and nonreadability. Restoration creates a new texture and checks its actual format. Source-content hashes and game/Unity/device/settings identities make accidental stale reuse less likely than package-ID or timestamp-only keys. Prepared keys additionally bind provider selection and logical/physical source identity; they are conservative enough that mod-order/selection changes can invalidate otherwise reusable entries. See [PNG keys](../../../src/WakeUp/Textures/PngRuntime.cs:69), [capture](../../../src/WakeUp/Textures/PngRuntime.cs:368), [restore](../../../src/WakeUp/Textures/PngRuntime.cs:506), and [prepared identities](../../../src/WakeUp/Textures/PreparedTextureRuntime.cs:33). A validated image cache is still not an independently validated XML replay contract.

**Cache maintenance is a real product improvement.** A one-launch decision is latched centrally rather than consumed by the first cache; bypass prevents writes as well as reads; clear can run with caching disabled. Owned stores protect earlier entries until a complete checked replacement is published, recover recognizable interrupted writes, avoid deleting authored DDS, and reserve capacity before expensive capture. Read failures return to ordinary processing. See [launch policy](../../../src/WakeUp/Caching/CacheLaunchPolicy.cs:10), [store admission/publication](../../../src/WakeUp/Caching/OwnedCacheStore.cs:151), and [PNG maintenance](../../../src/WakeUp/Textures/PngCache.cs:58).

**Leaf-subclass and routing changes preserve important native ownership.** The leaf proof supplies only an empty native child list when justified; existing lists and native iteration remain authoritative. Its bounded constructor lifetime fixes the earlier implementation's failure to reach normal colony entry. Routing returns the current holder's object, tracks dictionary/list changes, does not retain missing results, and owns no textures. These are meaningful improvements over a global stale result dictionary. See [leaf proof](../../../src/WakeUp/TypeSearch/LeafSubclassIndex.cs:35), [constructor lifetime](../../../src/WakeUp/TypeSearch/LeafSubclassRuntime.cs:115), and [route lookup](../../../src/WakeUp/Assets/AssetRouteCache.cs:48).

**Compatibility is usually local rather than all-or-nothing.** Required method behavior is checked instead of equating every new game version with failure; unsupported optional suppliers can retain ordinary loading while other features run. Harmony still has an exact binary gate. This reduces unsafe assumptions, but also means a checkbox is a request, not proof that useful work occurred. The independently found routing exception below prevents an unconditional claim that every published patch kind is handled correctly.

### F1 — Routing omits two published patch kinds from its compatibility check

**Actionable source defect; no affected real mod or corrupted run demonstrated.** [AssetRoutingPatchGuard.Allows](../../../src/WakeUp/Assets/AssetRoutingPatchGuard.cs:42) inspects ordinary prefixes, postfixes, transpilers and finalizers but omits `InnerPrefixes` and `InnerPostfixes`. These are additional method-interception categories exposed by the pinned Harmony. The common [PublishedPatchGuard](../../../src/WakeUp/Compatibility/PublishedPatchGuard.cs:78) explicitly includes both; the retained-world correction therefore did not cover this separate routing guard. The omission also exists in the preserved compiled output, [routing guard instructions](../../../artifacts/ordinary-entry-package/package-review/accepted-il/WakeUp.il:902).

The concrete risk is a remembered lower-priority supplier when a higher-priority holder's `Get` method gains an inner hook that can supply a texture without changing `contentList`. On a route hit, [higher-provider checks and winner lookup](../../../src/WakeUp/Assets/AssetRouteCache.cs:63) validate higher holders' dictionary stamps but call `Get(path)` only on the remembered winner. The new higher-holder behavior is skipped, although a native scan would call it. The route guard can falsely approve that state. This is not a claim that all inner hooks on `ContentFinder.Get` itself are skipped; those can wrap the rewritten body.

Fix by including both inner categories in the routing guard's existing decision. Add one focused regression for published inner records and route refusal, reusing the existing testing mechanism; [background guard tests](../../../tests/WakeUp.Tests/BackgroundLoadingTests.cs:482) already exercise such records. Existing [routing foreign-hook coverage](../../../tests/WakeUp.Tests/AssetRouteCacheTests.cs:175) tests an ordinary prefix. A new general compatibility framework is unnecessary. Runtime impact remains conditional until an actual affected combination is demonstrated; this is nevertheless a correctness hole worth fixing before broad release.

### F2 — Native preparation admits less than its advertised output size might suggest

**Demonstrated code limitation, not texture corruption.** The public window predicts output as full uncompressed RGBA32 mip data, then refuses it before invoking native capture. [EstimatedPixels](../../../src/WakeUp/Textures/TexturePreparationWindow.cs:135), [scan admission](../../../src/WakeUp/Textures/TexturePreparationWindow.cs:119), and [start admission](../../../src/WakeUp/Textures/TexturePreparationWindow.cs:182) impose this conservative limit even if the actual native compressed texture would fit.

For example, a 2048-square full mip chain is about 22.37 MB in RGBA32 but about 5.59 MB in BC3/DXT5, below the prepared store's 8 MiB complete-entry allowance after its small manifest. These are layout calculations, not a measured claim that every such image qualifies for DXT5. The [original preparation decision](s10-preparation-decision.md:112) already records the format-dependent sizes. The final public path cannot reach that potential coverage. The captured ReGrowth JPEG was also refused by conservative admission; its actual cache result must be read separately, not assumed to be an eligible compressed counterexample.

A useful follow-up is bounded, format-aware admission using verified native output rules, or a carefully bounded native capture whose final output is checked before publication. Keep decoder/GPU memory limits distinct from disk-payload limits. This can broaden real coverage without raising the whole-store budget, but its benefit needs a naturally eligible workload. It is not a reason to rerun the one-texture comparison.

### F3 — Activation and cache information is incomplete for ordinary users

**Source-established user-experience gap.** Routing writes “active” at initialization; a later foreign-hook refusal or caught lookup exception clears routes and returns native behavior without updating that status ([initial status](../../../src/WakeUp/Assets/AssetRoutingRuntime.cs:56), [later fallback](../../../src/WakeUp/Assets/AssetRoutingRuntime.cs:79)). Settings continue showing the old status. Translation and several supplier options expose checkboxes without equivalent current refusal/use summaries ([settings](../../../src/WakeUp/Startup/WakeUpMod.cs:88)). Their logs can explain activity to a developer, but the ordinary user cannot readily distinguish selected, admitted, hit, and no eligible work.

The display samples only the PNG/JPEG cache ([snapshot](../../../src/WakeUp/Textures/PngRuntime.cs:31); [formatting](../../../src/WakeUp/Startup/LoadingDisplayState.cs:70)); it does not summarize prepared hits, Gagarin ownership, translation work or supplier refusals. On the all-selected workload it refuses entirely because Loading Progress owns the screen. Prefer a small persistent settings summary with actual state and a short reason, reusing existing counters rather than adding a profiler or per-item log writes.

### F4 — “Mod names stay hidden” does not remove native mod-list drawing

**Coverage/wording issue, not an established startup regression.** The settings [claim](../../../src/WakeUp/Startup/WakeUpMod.cs:97) and S08's [names-hidden wording](s08-loading-display.md:17) apply to Wake-Up's own count-only panel. [InstallHooks](../../../src/WakeUp/Startup/LoadingDisplayRuntime.cs:101) adds a postfix and [Draw](../../../src/WakeUp/Startup/LoadingDisplayRuntime.cs:187) explicitly preserves native drawing. It does not suppress the game's separate `ModSummaryWindow`. Thus No Modlist on Loading's documented removal feature remains missing and should appear explicitly in retained coverage.

The [native UI research](../../../artifacts/s08/research/native-ui-notes.md:34) also says the summary requires a current game/UI and suitable event; normal menu-first startup can have no eligible summary work. Its absence is not evidence of a missing large menu saving. Clarify the text now; implement scoped suppression only if a concrete loading path renders costly unnecessary names/icons.

### Resource costs and bounded tradeoffs

Automatic image storage and prepared storage can each occupy 512 MiB and duplicate the same texture. Preparation resolves first, so two populated stores do not imply two saved decodes. Cache publication uses multiple managed byte copies plus checksum validation and synchronous durable file flushing; native GPU capture can wait for readback. These costs are visible in [store publication](../../../src/WakeUp/Caching/OwnedCacheStore.cs:179) and [compression capture](../../../src/WakeUp/Textures/PngRuntime.cs:470). Limits constrain entries/disk ownership, not complete engine peak memory. This audit found no measured process-memory result establishing the latter.

Routing is not a constant-time lookup on a hit: it checks every higher-priority provider's holder stamp. A complete holder miss performs its own scan and then repeats the native scan before Resources/bundle fallback ([route miss](../../../src/WakeUp/Assets/AssetRouteCache.cs:81), [runtime fallback](../../../src/WakeUp/Assets/AssetRoutingRuntime.cs:80)). Those are explicit costs paid to preserve dynamic overrides. Their real distribution and total cost were not captured by the two-hit functional probe. Do not describe two hits as a measured startup saving.

The background/display features primarily improve interaction, not CPU throughput. The display avoids per-item waits and formats on a 250 ms budget; native main-thread work can still hold the last frame. Background support retains carefully bounded load lifetimes and current preferences, rather than changing global gameplay behavior. These are useful qualities even when a menu benchmark cannot credit them.

### Established causes versus plausible explanations

Established limits on new benefit are: the old release already did most useful work; defaults keep new optional algorithms off; many ambitious goals were not integrated; some additions act after menu or improve interaction only; the texture workload has almost no eligible native image work; Gagarin skips existing search work on warm hits; Loading Progress prevents other selected Wake-Up features from executing. These are observed/code-backed explanations for the small amount of new work available.

Plausible but unquantified explanations include compatibility-check/index overhead in the small default regression, routing's repeated provider/miss costs, and system variation affecting the exact warm difference. Translation is a credible major contributor based on stage measurements, but its independent whole-menu share is unproven. English could offer less translation work, yet **English speed is unmeasured**. No result proves the retained algorithms hit a universal technical ceiling.

## Replacement verdict and practical removal guidance

No evidence supports telling users to remove the entire researched ecosystem and keep Wake-Up. Most entries provide capabilities it does not deliver; several broad tools also have gameplay or management purposes explicitly outside this assignment.

* **Keep Prepatcher:** it is required infrastructure, not a replacement target.
* **Keep a supplier when relying on its feature:** Wake-Up's Gagarin assistance is not a persistent XML cache without Gagarin. Its Loading Progress coalescing, Character Editor preset reuse and Giddy-Up readback likewise require those mods; removing them removes the assisted behavior. Character Editor and Giddy-Up are not extra inventory entries, but their contribution matters to interpreting the benchmark.
* **Loading Progress can be replaced only by accepting reduced display/profiling capability.** Wake-Up can show a basic independent panel when Loading Progress is removed; that is not proof equivalent progress detail, diagnostics, or loading implementation survives. No current replacement head-to-head was measured.
* **Do not remove conversion tools merely because preparation exists.** Native-output caching lacks their broad DDS quality/resize workflows and cannot prepare a first startup before reaching the menu. Removing a manager executable and removing already-generated texture files are different actions; this audit proves no cache/export/uninstall migration for them.
* **Narrow overlap can justify an individual choice, not equivalence:** a user who wants only supported live XML/type search optimization may choose Wake-Up over an older narrow optimizer while knowingly giving up extra features. This is not a demonstrated same-performance removal recommendation for FGL, YaOpt, Hyperdrive or Performance Fish.
* **No Modlist, Startup Impact and general Load in Background behavior remain distinct.** A count-only startup panel, bounded stage history, and scoped save/world background permission do not fully replace those documented functions.

The two legacy Wake-Up conflicts are supported duplicate-product warnings. Other mods sharing a topic do not automatically warrant `incompatibleWith`; runtime refusal can allow coexistence while reducing active Wake-Up features. Conversely, **no warning** and **safe fallback** are not proof all combinations have been tested. Removing a competitor to unlock one Wake-Up feature can also remove a more valuable feature. The correct decision compares the retained capability and whole-load result, not which checkbox becomes active.

Consequential claim corrections are:

1. **“Full replacement” / “all-loading support”: unsupported.** The retained report and current-state summary already reject these claims; the old ambitious plan title does not restore the missing capabilities.
2. **“All options active” or “every feature faster”: unsupported.** The warm report correctly says selected. Display/diagnostics and Gagarin assistance refuse, leaf/background act outside the menu endpoint, and populated PNG storage yields zero hits.
3. **“About 55–56% improvement from the revamp”: wrong attribution.** Most absent-to-new benefit already existed in public 0.2.1, and absence contains other optimizers. Report the old-to-new differences and cache/language conditions.
4. **“Texture preparation supplied the 2.54 seconds” or a preparation break-even: unsupported.** One shared useful image and no isolated preparation control do not allocate bundle gains.
5. **“Names hidden” means the native list is removed: misleading.** It refers only to Wake-Up's panel; the independent No Modlist behavior remains unimplemented. The panel also ends at startup and does not restart for subsequent save loading ([lifetime](../../../src/WakeUp/Startup/LoadingDisplayRuntime.cs:160)).
6. **“BetterLoading was only a UI reference”: incomplete original research.** Its historical active parallel XML and separate native type memo require explicit disposition; its unhooked parallel def-construction method must remain excluded.
7. **“Safe fallback proves universal compatibility”: unsupported.** Guarding is valuable, but coverage is narrow and F1 shows a specific missed patch category. Gagarin's independent cache validity remains its supplier's responsibility.
8. **“Ordinary entry is still wholly untested” or “the engine risk is fixed”: both wrong.** Three manual native paths passed, including the final DLL; earlier automated present/absent stalls and persistent InputLegacy errors remain. Current summaries supersede historical pending-review paragraphs. The [user guide's older workaround-only paragraph](../../user-guide.md:73) is easy to misread beside its later ordinary-entry update and should be consolidated, not used to erase newer evidence.
9. **“English or current Linux is faster/qualified”: unestablished.** Both timing series were French on Windows; earlier Linux evidence belongs to other packages. Attempted forward compatibility is not current platform qualification.

No new runtime tests were run. Existing offline checks establish specific logic/contracts; live menu passes establish startup; sampled texture/translation checks establish their sampled behavior; manual entry establishes those observed user paths. None alone proves long-colony compatibility, every mod combination, source-cold performance, complete process-memory bounds, safe competitor uninstall, or stable public release readiness. No new blocker should be inferred merely from a hypothetical failure this audit did not demonstrate.

No score or universal speed percentage is assigned. The practical result is a stronger, maintainable incremental optimizer with incomplete replacement coverage. The next useful choice is whether to pursue one of the large missing capabilities deliberately, or present the narrower product honestly and improve its actual eligibility and feedback.
