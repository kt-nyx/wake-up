# Character Editor preset preparation: optional reintegration

This change restores faster preparation of Character Editor’s item/turret UI presets. It reuses a read-only lookup during the original startup construction instead of repeatedly scanning and sorting the same definitions. It does not skip presets or change their settings. The owner explicitly expanded scope to permit individual-mod improvements with safe soft dependencies on 2026-09-07.

The historical implementation from `1f33fd5` was removed by `f886277` for the former general-only scope, not because it failed to execute. It is adapted to the current runtime on `codex/character-editor-reintegration`, starting from local main `4d253ab231dc3977b34bdccdcde1b54d536ffdc4`. The historical combined 51.6% result is not a measurement of this isolated feature or the new package.

## Optional compatibility

Character Editor remains optional and is neither linked nor bundled. Activation requires the user-selected candidate feature, the reviewed game/Harmony identities, Character Editor assembly version `1.6.3.3`, module ID `3db27871-e2d8-425d-98d1-a758fe85d3bd`, and complete DLL SHA-256 `BFF3B2268321F8C9566E15CBBD71CA6F975E9139F976C8BD4A9E0CA924C5B457`. The nine inspected method bodies are checked before their metadata tokens are used for patching. Generic method instances and the complete relevant preset chain must have no foreign Harmony hooks; a changed patch publication during a scope disables reuse. This is a compatibility pin, not a forced mod installation/version lock. A supplier update can disable the optimization while its normal code continues.

Only the first startup object and turret construction calls can borrow one original dictionary per synchronous scope, bounded to 4,096 entries. Definition-list replacement or membership/order changes, nested calls, foreign-thread use and later menu/gameplay calls retain ordinary lookup. The original constructors, return objects, dictionary order and exceptions are preserved. Scope finalizers release our reference without clearing the original object, including exceptional exits. Separate preset-content digests record stored values without invoking supplier getters; controls and candidates use the same observation.

## Validation

The final runtime package is `743ecabb5043d360698b90815895c5fbab7f95a5`. All 66 managed tests and 29 Python fixture checks pass with zero build warnings/errors. Tests cover the exact physical supplier and its nine method bodies, same-version/changed-byte rejection, module/version mismatch, changed patch publications, ordered dictionary reuse, invalidation, bounds, cross-thread fallback, exception propagation, release and preset-content digest sensitivity.

The first prepare (`ce-q01-control`) was held offline because the new selector was omitted from final command reconstruction; fixture regression coverage and commit `dff1c5f` fixed that before launching. Initial runtime `5cea56c` completed original/candidate qualifications (`ce-q03-control`, `ce-q04-candidate`) with identical stored preset digests, but the candidate's newly added admission restriction prevented reuse. No speed claim uses that candidate. The final runtime restores the historical per-calling-thread scope behavior and closes admission only after a completed, original main-menu repaint; it does not assume Character Editor's startup constructor must run on the Unity main thread.

Successful final qualification `ce-q05-candidate` built one dictionary in each scope, served 3,865 reuse hits, preserved all 3,827 object and 40 turret presets, reported zero fallbacks/exceptions and retained zero entries after both scopes. Stored values matched the original path exactly: objects `6DE6FA83E4A68D8747130F7DDB5162535049D11BEEE0E76550EE7C10E1059B62`, turrets `B4560AA0BF6B87DDEA611E4E72739501698BC309C3B291CF8106904DDF871849`.

The final forward/reverse comparison uses the same package, searches, Gagarin/PNG selectors, diagnostics, profile, content, order and independent menu observer, changing only preset mode `timing` versus `on`. All application caches start fresh; operating-system file caches are not flushed. Original scope timing and preset-value receipts are enabled in both arms. The host remains otherwise idle according to the game inventory before/after each run, with the same fixture-only below-normal CPU priority. The workload is the existing 30-package patch-heavy selection plus Character Editor (31 content packages, 33 with RLO and the observer), dependency-checked and sorted with the already qualified author/community rules. No larger fixture is needed to show this effect. Character Editor is temporarily restored only inside the fixture for a separately sorted `biocombat-ce` selection. Existing representative selections remain unchanged and Character Editor-free. Normal Steam, Workshop, profile, save and cache state is untouched.
