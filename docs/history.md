# Results and stopped approaches

This summary preserves decisions that matter for future work. It is not a work
queue or authorization. Detailed tracked records remain in private Git history
and the [published 0.3.0 documentation](https://github.com/kt-nyx/wake-up/tree/v0.3.0/docs).
Ignored raw artifacts are local working data, not permanent source history.

## Released 0.3.0

See [release notes](release-notes-0.3.0.md) and
[publication receipt](release-0.3.0-publication.md).
Recorded Windows Steam qualification found ordinary defaults effectively tied
with native on a small English workload. Separate workloads supported code
searches, French translation application and warm PNG reuse. Their gains cannot
be added or generalized. Texture-cache construction adds time and disk usage;
enabling all options was not a useful preset. Linux/Deck was not qualified.

Earlier losing routes included independent parsed-XML reconstruction, inheritance
caching, ordered read-ahead, parsed-language persistence, faithful authored-DDS
recaching, managed first-build decoding and static atlas caching/batching.
They remain inactive in the release. On-demand loading, progressive detail and
the companion app were not delivered.

## Rejected post-release campaign — 22–23 September 2026

Three bounded mechanisms passed targeted GOG correctness checks, then failed to
earn adoption during owner-authorized light-browsing performance comparisons.
Forward/reverse controls measured complete startup against unchanged 0.3.0.
No browsing sample was excluded to improve a result.

| Trial | Difference from released 0.3.0 |
| --- | --- |
| Direct PNG decoding | First construction 1.894 / 3.055 seconds slower |
| Direct decoding plus early preparation | First construction 2.147 / 2.207 seconds slower |
| Early combined XML restoration | Fresh 0.570 / 0.769 seconds slower; warm 0.685 / 0.876 seconds slower |

Image warm differences and the incremental overlap effect changed sign.
Released warm texture reuse remained useful. The image comparison shared a
PNG-selection bridge; it was not optimizer-absent startup, because removal would
select authored DDS siblings. Its unusually slow first native sample was retained
and its cause left unestablished.

There were 16 counted image and 10 counted XML captures, plus one declared XML
warmup. Image evidence received independent final review. The owner stopped work
before final independent XML performance review; its figures are the measurement
owner's reported results, not completed independent acceptance.
The fixture was restored before repository cleanup.

The user stopped testing/iteration, then requested release restoration and
cleanup. No rescue loop, combined adoption or publication followed.
Former campaign state is preserved in private history at
`8572d7b0ed3eb84ff876a37a7b327c500fb169eb`; image report handoff is
`10ff8d066b0519cc8ca75f6056a554e69ac49c13`.
The restoration commit retains this ancestry while reverting product code.

A failed implementation does not disprove its entire technique. Reopening needs
a materially different evidence-backed premise that addresses the measured costs;
fewer checks or operations alone are not evidence of useful speed.
