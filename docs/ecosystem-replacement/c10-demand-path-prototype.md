## Scope and compatibility boundary

The process argument `--wake-up-demand-textures=on` selects the experiment only
with candidate startup mode. No normal setting enables it. Without the argument,
the existing texture/audio bridges continue their ordinary paths.

File discovery uses the existing C05 provider and folder selection, including
native DDS precedence. Supported `ContentFinder<Texture2D>` requests use the
existing prepatched native provider search. C09's memoized routes assume fully
populated holders, so this experiment falls through to that native search while
private textures are active. A route still belongs to its actual provider.

Known public holder access completes the holder before exposing its dictionary.
Existing or duplicate entries keep native eager reload behavior. Native holders
own all published objects and their disposal. Metadata teardown creates nothing.
Removed files preserve native null-result publication and dictionary/path-index
consistency. The private path index (trie) retains original source order; supported
folder requests complete matching values before native enumeration. Repeated
public holder access does not invalidate an existing dictionary enumerator.
Prepared records use C05 native source/platform identities and representation
validation; an absent or invalid record falls back to native loading before
publication. Reduced-quality C08 records are not native-demand output.

The bounded graphic population is exact native `ThingDef`/`GraphicData` with
realtime drawing and supported native graphic classes. Atlas populations, pawn
race icons, custom definition classes and color callbacks stay eager. Supported
native graphic/UI requests complete retained callbacks in their original order.
The native dynamic-drawing initialization hook prepares dependencies on the main
thread before worker dispatch; actual colony parallel drawing remains untested.
An undeclared worker request for a pending holder entry fails promptly;
it never waits for a main thread that might be waiting for that worker.

Unknown direct dictionaries, reflected fields and undeclared worker first use
are outside the approved prototype's compatibility promise. They are not
automatically detected or made safe. The observer deliberately checks an absent
raw dictionary entry as a negative case. These limits require a separate owner
decision before any release proposal.

One real VEF startup consumer enumerates texture names under a prefix and then
constructs materials. Its exact `ExpandableGraphicData.LoadAllFiles` body and
static constructor are pinned. The scoped integration completes that prefix's
population before original enumeration; order, duplicates and subsequent native
material construction remain unchanged. The holder/trie does not escape this
verified method. Accessor construction helpers have published-patch guards,
including closed generic calls. Unsupported suppliers retain whole-holder
completion. This is not a package-wide VEF exemption or universal reflection check.
