## What the new consumer does

The game selects files using its normal folder precedence and enumeration. A coordinated Prepatcher boundary receives that actual ordered selection before native asset construction. It captures immutable bytes in contiguous bounded groups; the same bytes provide content hashes and, on a miss, parser input. The key includes the complete selected-path sequence, ordered active mods and effective folders, source bytes, game module, XML-library modules, parser policy and output schema. No timestamp, package allowlist, alternative filesystem crawl or supplier cache determines freshness.

Each group is an independently complete reusable generation in `WakeUp/ParsedXml/v1`. One `OwnedCacheStore` session owns the category; entries are integrity-checked and atomically published through its existing envelope. Groups aim for 4 MiB of source input or 512 files; a single file can use the existing 16 MiB file limit. Per-mod capture is limited to 32 MiB/8,192 files, and serialized payloads to 32 MiB. These are resource bounds, not a minimum-work performance heuristic. Refused groups use native loading.

On a warm hit, the platform binary XML reader supplies names and values once while constructing **two separate mutable native trees**: the source tree and its corresponding destination nodes. This avoids text parsing and the second source-to-destination deep-import traversal for represented files. Real `LoadableXmlAsset` constructors receive their own staged source document after their ordinary attribution assignments. Files retain their real name, full folder and mod; the combined map points to those actual new assets.

Source and imported empty-element semantics differ: the source retains explicit empty-pair syntax while native import normalizes a childless destination element. The format preserves that distinction. XML declarations and empty-element metadata accompany the binary stream. Namespaces, CDATA, processing instructions and other unrepresented shapes parse/import natively per file. First construction compares restored source **and imported-root structure** with native results before retaining a record. It does not silently normalize unsupported source trees.

This differs from S04's losing per-file general node encoding: groups share storage work, and warm reconstruction creates source and destination nodes in one traversal. Both sets of node allocations remain necessary. It differs from R1/R4b by doing no late document replacement, patch-prefix replay or retained-node edit journal. These changes establish a different implementation premise, not a performance result.

## Publication, compatibility and fallback

Objects remain private until actual source asset construction. Before the first constructor, a failed read, corrupt generation or changed observer can discard the whole staged batch and use native processing. After constructors execute, the batch is never replayed. A late incompatible observer discards prepared combination and calls native combination once on the actual existing source assets, preserving retained references and mutations.

The combination boundary prepares a complete destination/map pair privately and publishes it by reference assignments. Native malformed-input and wrong-root messages remain at their corresponding stages. Native patches, custom operation callbacks, inheritance, definition construction, cross-references and downstream initialization remain in their normal order. Hot reload clears dependent session products and uses native processing.

Admission checks original Prepatcher inputs and effective runtime bodies, including the selected-file loader, enclosing loading call, constructor, `LoadDefs` iterator, source-loading and combination methods. All relevant Harmony hook categories are checked again at consumption/publication through the existing publication-stamp guard. The coordinated R4a constructor bridge and existing XML timing callbacks remain supported. Unknown observers use native behavior rather than a broad owner-name exemption. Optional Gagarin discovery still runs and its absence can remove its hooks before the actual source consumption boundary.
