# C04 — native parsed language reuse

**11 September 2026 — steward functional review passed. Performance pending, not fully accepted.**

C04 remembers native language data before it is applied to game definitions. On a matching later load, the real game loader consumes fresh ready records for interface text (keyed translations), named text lists (Strings), and translated definition fields (DefInjected). The existing optional translation-application optimization remains separate and unchanged. New persistence defaults off.

## Source decision and actual consumer

The assigned clean base was `e431e6679f9883b3f6a1c052eeeadd73728784a6`, on the preserved `codex/ecosystem-next-plan-review` ancestry. Main remains unmerged. Original GOG methods were inspected; the historical Steam research was not treated as the runtime contract.

Historical S06 grouped-language operation replay repeated parsing-like merge work. R4c changed decoding but did not establish repeatable benefit. C04 instead captures native results before application and restores the final changed entries for a native source group. It does not replay file operations. Cold loading runs the native parsers once; warm loading skips their XML parsing and record construction. This is a materially different consumer boundary, with performance still to be measured.

`ParsedLanguageRuntime` replaces exactly two indexed parser loops inside `LoadedLanguage.LoadData`. Native directory/archive discovery, source registration and order, parallel reads, legacy-folder warnings, icon callbacks, empty-package creation and WordInfo stay in the original method. Strings restoration occurs after its native successful read and catch region. The native application passes before and after implied definitions still execute, including aliases, list replacement, native setters and retry behavior. The retained S03 application path remains independently selected.

Each warm group updates its existing dictionaries in place, restoring only changed entries. Existing untouched records retain identity; Strings appends only the group's lines to existing lists. Decoding creates new records and lists for each owner. No Def references, success flags, normalized paths or replaced values are persisted. Error/unsupported groups retain native behavior at their original boundaries; keyed whole-file errors and partial injection errors are not cached as successful groups.

## Identity, compatibility and lifecycle

Keys bind actual consumed text and path/order, previous parsed state, selected and default languages, effective mod/folder order, consumed code/module identity and relevant Def-name lookup state. Filesystem and native tar sources are admitted; arbitrary providers remain native. Parser, merge, generated iterator, converter and relevant lookup methods have fixed original-GOG contracts. Unknown shared Harmony callbacks refuse the affected load. Unsupported name-conversion callbacks are scoped to native injection parsing; independently guarded keyed and Strings groups can still reuse data. Changed transpiler input remains untouched, preserving foreign instructions. The native random legacy Neurotrainer rename remains uncached when it depends on choosing a missing original definition's replacement.

Sessions end with each LoadData call. Native clear invalidates an active session; reentrant or contended calls cannot share it. The owned `ParsedLanguage/v1` store shares the existing 1 GiB total budget and maintenance policy. One-launch bypass/rebuild/clear apply, including clear while disabled. Decode and preparation failures fall back before publication; after a live merge starts, an exception cannot replay native work over partial state. Existing owned-store integrity/quota behavior supplies disk fallback.
