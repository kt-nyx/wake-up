## How to read acceptance

**Owner-approved sequencing update, 10 September:** independent functional coverage, correctness, compatibility and expected-behavior review permits the next implementation slice while performance remains pending. Continue through the sequence; do not impose a batch limit or stop merely for an unavailable unattended window. Full acceptance still requires the joint criteria below. Each slice retains a named owner, exact implementation/evidence and pending measurement obligations; later individual and combined performance tests cannot be replaced by a combined total that hides a regressing feature.

A supplier can be removed for a capability only after Wake-Up executes that capability with the supplier physically absent from the isolated workload. Selecting an option, finding a hook, recording a cache hit on a synthetic input, reaching the menu, or refusing safely does not meet that test. Every row requires its stated user behavior, agreed coverage, correctness, compatibility and applicable performance evidence. These conclusions are recorded separately but jointly gate slice acceptance. Optimization rows require a repeatable useful gain on agreed workloads, not merely fewer operations; non-speed features require their stated benefit and acceptable measured overhead. Performance testing is limited to explicitly declared unattended windows under the [standing policy](next-campaign-proposal.md#standing-operational-permission-and-pc-availability). A functional pass with performance pending is not acceptance. Release approval remains a later gate.

The original nine goal numbers are retained. Letter suffixes split independently observable behavior so one narrow implementation cannot close a larger goal. **P** means source or shipped-DLL mechanism checked in this research or its pinned detailed source evidence; **D** means author-described behavior with unavailable implementation; **N** means current native game coverage. P is not an execution or quality rating. References to prior reports below resolve at `fe687d4` as described in the evidence document.

For all cache rows: first construction, a later actual hit, content/order/settings change, corrupt entry and ordinary fallback must work. For all deferred rows: off means ordinary readiness, on requires useful avoided eager work, and gameplay/first-use checks are mandatory. A narrow first increment can be accepted as that increment; its parent stays incomplete until all rows are accepted or the owner approves a named exclusion.

## Retained integrations and native coverage

C01–C15 preserve the existing supported Character Editor preset reuse, Giddy-Up texture readback, Gagarin assistance and Loading Progress bridges when their suppliers are installed. These are optional improvements to those suppliers, not replacements for their editor, riding, gameplay or display functionality. The owning slice checks an integration when it changes the shared XML, texture, method-patch or session boundary it uses; C15 checks the combined configuration. No new supplier dependency may be introduced to satisfy a replacement row.

Native DDS loading, type-name/construction-delegate caches, lazy previews and native startup background behavior also require explicit supplier-absent confirmation in their owning rows (C05, C12, C13 and C14). They count as preserved game behavior; they do not create a requirement for duplicate Wake-Up mechanisms. Existing native hooks, query indexes and optional integrations must remain correct when an independent cache hits or falls back.

## Completion rule

All current-release rows and their supplier-removal conditions stay open until accepted. Row 6c remains unaccepted optional post-release, explicitly excluded from current release/successor gates; external-tool guidance must still disclose its absence. In particular, **1a is not 1b/1c, 2a is not 2b, 5a is not 5b, 6a/export is not 6b/c, and 8c/two XML timers are not 8a/b**. A losing approach does not alter this matrix. The dated 6c amendment authorizes this deferral; any further reduction, postponement or exclusion needs an owner decision.
